Introdução ao Git & GitHub

Módulo I - Introdução ao Git

O Git não serve apenas para código, mas também para rastrear a evolução de qualquer arquivo de texto ao longo do tempo.

Controle de versão

O controle de versão é o mecanismo que permite rastrear as alterações em um arquivo ou conjunto de arquivos ao longo do tempo, saber quem fez, quando, por que e como restaurar uma versão anterior.

Colaboração

A colaboração permite que vários programadores trabalhem juntos em um código, mesmo que estejam geograficamente dispersos. Isso possibilita uma divisão de tarefas mais eficiente e facilita a resolução de problemas complexos.

Benefícios do controle de versão e da colaboração

  • Histórico completo de alterações
  • Rastreamento de responsabilidades e contribuições individuais
  • Recuperação rápida de versões anteriores
  • Paralelismo de desenvolvimento
  • Aumento da transparência

Ferramentas de controle de versão anteriores ao Git

  • CVS
  • SVN
  • Mercurial

Diferenças entre Git e GitHub

O Git é um sistema de controle de versão, onde você gerencia seu código localmente.

O GitHub é uma plataforma na nuvem que utiliza o Git para hospedar projetos de software e permite compartilhar e colaborar online.

Alternativas ao GitHub

  • GitLab
  • Bitbucket
  • Azure DevOps

Módulo II - Conceitos e comandos básicos do Git

Inicialização de um repositório

Um repositório é o diretório principal que contém todos os arquivos do projeto e o histórico de todas as versões criadas.

Cria um novo repositório Git no diretório atual:

git init

Comandos básicos: add, commit, status e log

Adiciona o arquivo à área de staging (começa a rastrear as alterações nesse arquivo):

git add <arquivo>

Configuração inicial

Antes de poder fazer commits, o Git exige que você se identifique, para saber quem fez cada alteração no histórico.

git config --global user.name "seu nome"
git config --global user.email "seu email"

Confirma as alterações no repositório e cria uma nova versão:

git commit -m "mensagem curta que descreve o propósito das alterações"

Para saber quais arquivos foram modificados, quais foram adicionados à área de staging e quais não estão sendo rastreados:

git status

Para ver o histórico de commits, quem modificou o quê, quando e por quê:

git log

Visualização e navegação no histórico de commits

Para visualizar os detalhes de um commit específico:

git show <commit_hash>

Para navegar entre commits apenas para consulta:

git checkout <commit_hash>

Desfazimento de alterações com revert, reset e checkout

Para reverter as alterações de um commit específico e fazer um novo commit:

git revert <commit_hash>

Descarta as alterações que ainda não foram adicionadas à área de staging com git add:

git checkout <arquivo>

Volta para um commit específico e apaga todos os commits posteriores, mas mantém as alterações desses commits no diretório de trabalho:

git reset <commit_hash>

Criação e gerenciamento de branches

Uma branch é uma linha independente de desenvolvimento. É como uma cópia do projeto em um momento específico, onde você pode alterar o código sem afetar a linha principal.

Comandos essenciais

Criar uma nova branch:

git branch <new_branch>

Ver todas as branches e identificar a branch atual:

git branch

Alternar para outra branch:

git checkout <other_branch>

Ou também pode usar:

git switch <other_branch>

Criar e alternar para a nova branch imediatamente:

git checkout -b <new_branch>

Apagar uma determinada branch:

git branch -D <branch_name>

Mesclar uma branch em outra. Você deve estar na branch que vai receber as novidades da branch secundária:

git merge <secondary_branch>
